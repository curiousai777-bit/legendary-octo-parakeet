# PortfolioAI Implementation Plan

## Phase 1 — Application foundation

- Web application shell
- Shared design tokens and responsive layout
- Authentication and role model
- PostgreSQL schema and migrations
- Seed data for initial niches
- API/service boundaries

## Phase 2 — Student onboarding

- Mode selector: interview, form, adaptive
- Niche selection/detection
- Dynamic question rendering
- Answer persistence
- Profile and evidence assessment
- Progress/resume support

## Phase 3 — Project engine

- Gap analysis
- Niche-specific project recommendations
- Project brief generation
- Milestones and evidence capture
- Student project workspace

## Phase 4 — Portfolio engine

- Niche-specific section templates
- Content generation from verified student data
- Portfolio editor
- Theme/layout selection
- Preview
- Version snapshots

## Phase 5 — Publishing and discovery

- Public portfolio URL
- SEO metadata
- Privacy controls
- Recruiter discovery
- College discovery
- Candidate saving

## Phase 6 — Quality and hardening

- Validation
- Authorization tests
- Responsive/accessibility review
- Error/loading/empty states
- Seed/demo account flow
- Deployment documentation

## Product quality rules

- Never invent student achievements or employment.
- Every generated claim should originate from student input or clearly be marked as a suggestion.
- The portfolio structure must adapt to the target niche.
- A beginner should receive a practical path to create evidence rather than being penalized for lack of experience.
- Students own and can edit their generated content.
